# Roger 0.27.0 Design

Release motto: "Make it so".

Roger 0.27.0 has four parts:

1. A log preset can also record system audio and then reads like a meeting ("Me" and "Other N").
2. Commands: a new Settings pane with configured shell commands (headless or in a terminal) that run after a log, a meeting transcript or a file transcript is saved.
3. The `ingest-roger` skill becomes a data-access skill. It teaches an agent how to read Roger. What the agent does with the content is left to the agent and its own skills (for Crystalline: `crystalline-capture`, "Ingesting a source").
4. Microphone priority: an ordered list of microphones with "System default" as one entry. Roger uses the first one that is connected.

## Goals

- A log of a call or a video holds both sides, labelled the same way as meetings.
- After Roger saves something, a user-defined command can process it without any manual step (for example Claude ingesting it into Crystalline).
- The skill stays generic for any Roger user and works best with Crystalline by handing processing to Crystalline's own ingestion method.
- With a Bluetooth headset switched off, Roger falls back to the webcam mic instead of the system default.

## Decisions

| Topic | Decision |
|---|---|
| System audio in logs | Per log preset toggle `recordSystemAudio`, default off. |
| Transcription of two tracks | Always the separate mic and system tracks through `MeetingTranscriptionPipeline`. Only the kept audio is mixed. |
| Kept audio | One mixed `.m4a` next to the entry. Logs have no retry, so separate tracks are not kept. |
| Echo without headphones | Not handled, same as meetings. |
| Commands storage | JSON in UserDefaults, like presets. No built-in commands. |
| Command triggers | Log presets ("After saving"), meetings (Library & Meetings pane), file transcripts (Files pane). |
| Prompt placeholder | `{prompt}` in the command line is replaced by the finished prompt, single-quoted for the shell. |
| Interactive terminals | Terminal, iTerm2, Ghostty and Warp, picked per command. |
| Concurrency | At most one headless run per command. Triggers during a run merge into one follow-up run. |
| Failure reporting | In the menu bar popover and the Commands pane. No system notifications, so no new permission. |
| Skill scope | Data access only. No engram rules, no domain argument. |
| Tasks and domains | Live in the command's prompt, not in the skill. |
| Skill name | Stays `ingest-roger`, so installed copies update in place. |
| Consumer | Optional argument, default `crystalline`, so existing ack state carries over. |
| Mic choice timing | Resolved at recording start. No switch during a recording. |

## 1. Log with system audio

### Preset

`DictationPreset` gets `recordSystemAudio: Bool` (default `false`), decoded with `decodeIfPresent ?? false`. It only matters when `output == .logEntry`. `withoutAI` keeps it. The built-in Log preset ships with `false`.

`PresetDetailForm`: in the `.logEntry` section, next to "Keep audio", a toggle "Record system audio" with the footnote "Also records what your Mac plays, for calls and videos. Needs the Audio Capture permission."

### Capture

When the active recording preset has `output == .logEntry` and `recordSystemAudio`, `startDictation` also starts a `SystemAudioTap` and collects its 16 kHz mono samples in memory, next to the mic samples of `AudioCaptureService`. A small `SystemAudioRecorder` (new, `Services/`) owns the tap, the consumer task and the sample buffer, and returns the samples on stop.

- If the tap fails to start (permission denied or no output device), the recording goes on with the mic only. The indicator shows "System audio unavailable" for the "Logged" moment, and the entry is saved as a mic-only log.
- The hotkey behaves as set (push-to-talk or toggle). The minimum recording duration applies to the whole recording as today.
- The meeting rules stay: no log recording while a meeting records.

### Transcription

When system samples exist, `runPipeline` takes a new branch for log presets:

1. `MeetingTranscriptionPipeline.run(mic: .samples(mic), system: .samples(system), ...)` with the same config the meetings use (diarize-mic setting, language pin from the preset).
2. The result is `[Paragraph]` (speaker, start time, text) with "Me" and "Other N".
3. The preset's post-processing steps run per paragraph. Speaker labels and times are never changed. When the AI guardrail fires, the non-AI text of that paragraph is kept, the same rule as for plain logs.
4. If the system track has no speech, the result has only "Me" paragraphs. That is fine.

When no system samples exist, the current single-text path runs unchanged.

### Entry

`LogEntryWriter` gains a paragraphs variant:

- Same folder and file name rules (`Logs/YYYY/MM/<yyyy-MM-dd HH-mm-ss>.md`), `tags: [log]`, same title rule (first words of the first paragraph).
- New frontmatter key `speaker_count`.
- Body: `# Log <time>`, then the paragraphs rendered by `MeetingTranscriptWriter.paragraphMarkdown`.
- Kept audio: mic and system are mixed (sample-wise sum, clipped to -1...1, the shorter track padded with silence) and encoded by `LogAudioEncoder` to one `.m4a`. The mix happens after transcription.

Logs without system audio look exactly as they do today.

## 2. Commands

### Model

New `Models/AgentCommand.swift`:

```swift
struct AgentCommand: Codable, Identifiable, Equatable {
    var id: UUID
    var name: String
    var commandLine: String        // e.g. "claude -p {prompt}"
    var prompt: String
    var workingDirectory: String   // "~" allowed, expanded at run time
    var mode: CommandMode          // .headless, .interactive
    var terminal: TerminalApp      // .terminal, .iterm2, .ghostty, .warp (interactive only)
    var timeoutMinutes: Int        // headless only, default 10
}
```

Stored as JSON in UserDefaults key `commands` by `AppState`. Every newer field decodes with `decodeIfPresent ?? default`.

Triggers:

- `DictationPreset.commandID: UUID?` (log presets only, decoded with `decodeIfPresent`).
- `AppState.meetingCommandID: UUID?` and `AppState.fileTranscriptCommandID: UUID?`.

A trigger that points to a deleted command shows "Missing command" in its picker and does nothing.

### Placeholders

Item placeholders: `{file}` (absolute path of the Markdown file), `{key}` (Roger key), `{title}`, `{kind}` (`log`, `meeting`, `transcript`).

- In the prompt they are replaced as plain text.
- In the command line, `{prompt}` is replaced by the finished prompt and each item placeholder by its value, every one single-quoted for POSIX shells (`'` becomes `'\''`).
- Unknown `{...}` stays as it is.

`CommandTemplate` (new, RogerKit, pure functions) does the substitution and quoting, so it is unit tested without the app.

### Commands pane

New `SettingsPane.commands` ("Commands") in the Library group after Agents. Built like the Presets pane: a list on the left, a `SettingsForm` editor on the right, with add, duplicate and delete.

- Fields: name, command line, prompt (multi-line), working directory (text field plus "Choose…"), mode, terminal (only for interactive), timeout (only for headless).
- A preview of the final command line for a sample log entry, read-only, monospaced.
- "Run now" runs the command for the newest library item (disabled when the library is empty).
- Last run (headless): time, status (exited with code, timed out, failed to start) and the last 20 output lines (stdout and stderr together). Kept in memory only.
- A footnote: "Commands run as you, with your login shell. Only add commands you trust."

"New command" starts from a Claude example:

- Headless: command line `claude -p {prompt}`, working directory `~`, prompt: "Use /ingest-roger to read what is new in Roger. Fold it into Crystalline with the ingestion method of crystalline-capture. Choose the domains by their routing. Keep tasks as [task] observations in the engrams they belong to. At the end, list the tasks you found."
- When the user switches the mode to interactive on an untouched example, the command line becomes `claude {prompt}` and the prompt ends with "...list the tasks you found and ask me which ones to work on."

### Suggest Commands

A link-style button "Suggest Commands" in the Commands pane opens a list of ready commands for the coding agents found on this Mac. Picking one adds it to the list.

- Harnesses come from the Agents pane detection (Claude Code, Codex, Gemini, Copilot, Kiro). A harness is listed when its CLI is found on the search path. Cursor has no CLI and is not listed.
- Each harness is offered "in the background" and "in a terminal window". A harness without a one-shot (headless) mode only gets the terminal entry. Only CLI flags verified with the CLI's own `--help` are used.
- The MCP config lookup of `HarnessRegistration.connection` is generalized to any server name. When `roger` is not registered in a harness, its entries are shown disabled with "Roger not connected, see Agents".
- When a Crystalline server is registered in that harness (a server named `crystalline`, or one whose command is the crystalline binary), the prompt is the Crystalline prompt (ingest with crystalline-capture's method, route domains, `[task]` observations, list tasks; the terminal version also asks which tasks to work on). Otherwise the prompt is: "Use the ingest-roger skill to read what is new in Roger. Summarize it and list the tasks you found."
- Prompts name "the ingest-roger skill", not `/ingest-roger`, because harnesses call skills in different ways.
- Headless Claude Code needs its MCP tools allowed up front: the line is `claude -p --allowedTools <tools> {prompt}` with `mcp__<server>` for roger and, when found, crystalline. Other harnesses get their own equivalent when they need one.
- "New command" starts blank. The example commands move into a tested `CommandSuggestions` builder (harness, Crystalline yes or no, mode → `AgentCommand`).

### Running

`CommandScheduler` (new actor, `Services/Commands/`) is the only entry point: `trigger(commandID:item:)`.

A trigger fires only after the Markdown file is written and `LibraryChangeRecorder.recordWritten` has finished for it, so `get_changes` already sees the item. Call sites: `saveLogEntry` (after `.saved`), `meetingRecorder.onTranscriptWritten` and the file transcript save.

Headless:

- `ProcessCommandRunner` runs `$SHELL -l -c <line>` (fallback `/bin/zsh`) in the expanded working directory with env `{PATH: CLILocator search path, HOME, USER, SHELL}` and the command's timeout.
- At most one run per command. A trigger during a run sets a "pending" flag. When the run ends and the flag is set, one more run starts with the newest item. Several triggers during a run give one follow-up run.
- A non-existent working directory fails the run with "failed to start" before any process starts.
- On failure the menu bar popover shows "Command <name> failed" with a button that opens the Commands pane. It disappears after the next successful run of that command or when opened.

Interactive:

- Roger writes `<temp>/roger-command-<uuid>.command` (mode 0700): `#!/bin/zsh -l`, `cd <quoted dir> || exit 1`, `rm -f "$0"`, then the line. It is opened by the chosen terminal:
  - Terminal: `open -a Terminal <file>`.
  - iTerm2: `open -a iTerm <file>`.
  - Ghostty and Warp: the launch method is checked during implementation (`.command` file through `open -a` if it runs the file, otherwise the app's own CLI or URL scheme). The plan has a task to verify each of the four by hand.
- Interactive runs are not queued. Each trigger opens its own window.
- A terminal that is not installed fails with "<Terminal> is not installed" in the same popover line.

## 3. The `ingest-roger` skill

`skills/ingest-roger/SKILL.md` is rewritten. It teaches an agent how to read Roger. It does not say what to write.

Description: "Read and ingest Roger log entries, meeting transcripts and file transcripts. Use when the user asks to ingest, import, sync or read Roger, or runs /ingest-roger."

Arguments: `/ingest-roger [consumer]`, default consumer `crystalline`.

Content:

- **Before you start:** call `status`. If the library is not ready, stop with `RESULT: failed: <message>`.
- **The loop:** `get_changes(consumer, summary: true)`, then fetch each kind once for the range with paging while `more`, then process, then `ack(consumer, upTo, library)` only when the whole range was processed. Library changed: start again. At most 5 rounds. Any failure: no ack, `RESULT: failed: <reason>`.
- **What an entry is:** kinds (log, meeting, transcript), events (`new`, `updated`, `deleted`, `missing: true`), `seq`, the Markdown body, screenshots by path (optional, skip what cannot be read).
- **Other tools:** `get_item`, `list_items` and `search` for reading outside the change feed (for example when the user asks about a past meeting).
- **Facts for any knowledge system:** `roger://<key>` is the stable address of an item. `seq` changes on every change of the item, so it works as a version. `updated` means the item must be read again as a whole. `deleted` means what was made from the item may need to go.
- **Frontmatter:** it is Roger's metadata about the file. Keys such as `type`, `status` and `tags` describe the Markdown file, not how the reader should store it. Decide yourself what the metadata tells you.
- **Processing:** "Process each item with your knowledge system's own ingestion method. With Crystalline, use the 'Ingesting a source' section of `crystalline-capture`." Nothing more.
- **Result:** the last line is `RESULT: ok`, `RESULT: ok more` or `RESULT: failed: <reason>`, as today.

`scripts/ingest-roger.sh` changes to `ingest-roger.sh <prompt> [max-runs]` and keeps its RESULT handling. `BundledSkillTests` checks the new required phrases (`get_changes`, `summary: true`, `ack`, `library: <library`, `roger://`, `RESULT: ok more`, `RESULT: failed:`, `crystalline-capture`) and that the old engram rules (`$contains_any`, `archived`) are gone.

## 4. Microphone priority

### Model

`AppState.selectedInputDeviceUID: String?` is replaced by `inputPriority: [InputChoice]`:

```swift
enum InputChoice: Codable, Hashable {
    case systemDefault
    case device(uid: String, name: String)   // name: last known, for display
}
```

Stored as JSON in UserDefaults key `inputPriority`. Migration on first load: a stored `selectedInputDeviceUID` becomes `[.device(uid, name), .systemDefault]` (name looked up, or the UID when the device is not connected), otherwise `[.systemDefault]`. The old key is removed after migration. `.systemDefault` is always in the list exactly once; loading repairs a list without it by appending it.

### Resolution

`AudioDeviceLookup.resolveInput(_ priority: [InputChoice]) -> String?` returns the UID of the first connected device, or `nil` for `.systemDefault` (meaning: use the default input). Every place that read `selectedInputDeviceUID` uses it at start:

- `AudioCaptureService.preferredInputUID` in `startDictation` and the mic test,
- `MicrophoneTap.preferredInputUID` in `MeetingRecordingService`,
- `SystemMicMute.targetInputDevice`,
- the device diagnostics in `runPipeline`.

### Microphone pane

- A list of the priority entries. Each row: name, "connected" or "not connected", up and down buttons, remove (not for System default, which shows the current default device name).
- "Add microphone…" menu with connected devices not in the list.
- A status line: "Roger will use: <name>".
- The pane listens to the Core Audio device list (`kAudioHardwarePropertyDevices`) and the default input, and refreshes the rows and the status line live.

## Error handling summary

| Case | Behavior |
|---|---|
| Audio Capture denied or tap fails | Mic-only log, short indicator note. |
| Diarization fails on a log | Mic paragraphs as "Me", system text as "Other 1" (the existing single-speaker fallback). |
| Command working directory missing | Run fails before start, popover line. |
| Command times out | SIGTERM, then SIGKILL to the group (existing runner), popover line. |
| Terminal app not installed | Popover line naming it. |
| Trigger to a deleted command | Nothing runs, picker shows "Missing command". |
| No priority device connected | System default. |

## Testing

Swift Testing, no `AppState` in tests.

- `DictationPreset` decoding: old JSON without `recordSystemAudio` and `commandID` decodes with the defaults.
- `AgentCommand` round trip and decoding of partial JSON.
- `CommandTemplate`: quoting of `'`, `$`, backticks, newlines and spaces; unknown placeholders kept; `{prompt}` gets the substituted prompt.
- `CommandScheduler` with a fake `CommandRunner`: one run at a time, many triggers during a run give one follow-up run, the follow-up gets the newest item, a missing directory fails before the runner is called.
- Interactive script writer: file content, mode 0700, quoting of the directory.
- `LogEntryWriter` paragraphs variant: frontmatter (`speaker_count`) and body against a fixture.
- Audio mix: lengths, padding and clipping.
- `InputChoice` migration and repair, and `resolveInput` against a fake device list.
- `BundledSkillTests` with the new phrases.
- By hand: a log with a YouTube video playing (Me and Other), Audio Capture denied (mic-only), each of the four terminals, headset off with the webcam connected.

## Out of scope

- Echo handling when no headphones are used.
- Switching microphones during a recording.
- Commands for presets that insert at the cursor.
- A run history on disk.
- Running a command from the Library window on a chosen item.
