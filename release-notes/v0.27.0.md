# Make it so

Roger now does something with what you say. A log can hear both sides of a call, and a command can take it from there: your coding agent reads the new entry and files it where it belongs.

## New & Noteworthy

- **Logs hear the other side too.** A quick note about a call is only half the story when it has only your voice. Turn on "Record system audio" in a log preset and Roger records your mic and the sound of your Mac. The entry shows who said what ("Me", "Other 1"...), and the kept audio is one file with both. If macOS does not allow system audio, Roger saves the log with your mic only and tells you.
- **Commands.** Settings has a new Commands pane. A command runs after a log, a meeting or a file transcript is saved, for example your coding agent with a prompt that reads the new entry. Pick it in a log preset, under Library & Meetings or under Files.
  - Background or terminal: a background command runs quietly, one run at a time. A terminal command opens in Terminal, iTerm2, Ghostty or Warp.
  - Placeholders: `{prompt}`, `{file}`, `{key}`, `{title}` and `{kind}` fill in the prompt and the entry. Roger quotes them for the shell.
  - Ask before running: a small panel asks "Allow" or "Not now" before each run. It does not take the focus from the app you type in.
  - Suggest Commands: Roger looks for the coding agents on your Mac (Claude Code, Codex, Gemini CLI, Copilot CLI and Kiro) and offers ready-made commands. With Crystalline connected, the suggestion uses it.
  - A failed run shows one line in the menu bar popover. Quit Roger and a running command stops too.
- **The ingest-roger skill only fetches.** Your agent knows best how to store what it reads. The skill now teaches it how to get the data from Roger: what is new, what changed and how to confirm it. What happens next is up to the agent and your knowledge system (with Crystalline: its own capture skill).
- **Microphone priority list.** You switch between a headset, a USB mic and the built-in one. Put them in order under Microphone: Roger uses the first one that is connected, and System Default is always the last fallback. When you plug in a mic higher on the list, Roger gets it ready right away, so the first words are not lost.

## Fixes

- **A dictation started during the mic warm-up could get cut short.** Right after launch, or while the Microphone pane tested your mic, a recording could stop early or come back empty. A recording now always wins.
- **Codex with `CODEX_HOME` showed as not connected.** The Agents pane only read `~/.codex`, and Connect and Remove changed that config. Roger now uses `CODEX_HOME` from your shell, the same way Codex does.
- **A Codex server written as an inline table showed as not connected.** `roger = { command = "..." }` under `[mcp_servers]` is read now.

## Changes

- **`/ingest-roger [consumer]`.** The argument names who reads the changes. The default is `crystalline`.
- **`scripts/ingest-roger.sh <prompt> [max-runs]`.** The script takes the prompt to run. Only the Roger tools are allowed by default. Add more servers with `EXTRA_MCP_SERVERS` (for example `EXTRA_MCP_SERVERS=crystalline`).

## Breaking changes

- **The skill's domain argument is gone.** `/ingest-roger jordi` now means consumer `jordi`, not domain `jordi`. That consumer starts from the beginning. Update a saved prompt: call `/ingest-roger` without an argument and say in the prompt where the knowledge goes, for example "Use the ingest-roger skill to read what is new in Roger and fold it into the jordi domain in Crystalline."
- **`scripts/ingest-roger.sh` no longer takes a domain** and no longer allows the Crystalline tools on its own. Pass a prompt and set `EXTRA_MCP_SERVERS=crystalline`.
